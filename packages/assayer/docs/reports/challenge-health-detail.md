# The Companion health report: shipped surface versus specified table · `rep:challenge:companion-health-contract-audit`

This report is evidence for a decision, not the decision. It compares the public Rust report to the binding Companion table, follows the divergence through its records and commits, and sizes the available reconciliations. It changes neither side. As a prose carrier it cites existing heads and mints none, under the label calculus.

The short result is asymmetric. `ChallengeHealthDetail` has six Rust fields. Five implement three of the specification's nine semantic rows, while `sufficient_evidence` is the only detail field with no row. Six table rows have no shipped report field. The enclosing `channels` map is the per-channel envelope, not a tenth health datum. No production path in this repository calls the report or reads any of its fields.

## The complete shipped surface · `sec:challenge:companion-shipped-surface`

### The envelope and producer · `sec:challenge:companion-report-envelope`

`ChallengeHealthReport` is a public, cloneable, debuggable report whose sole field is `channels: HashMap<ChannelId, ChallengeHealthDetail>`. Its derived default is an empty map. The detail is likewise public and cloneable and has a hand-written default (`packages/assayer/src/risk/challenge.rs:595-633`). The map has no ordering contract. Every member is public and neither struct is marked `non_exhaustive`, so hosts may construct and destructure the exact shapes; an addition is a Rust compatibility event as well as a Serde-schema change. Both types are re-exported at the crate root, so they are host-facing API rather than private implementation (`packages/assayer/src/lib.rs:153-160`).

`ChallengeEffectivenessTracker::health_report` is the only producer. It walks the tracker's stored channels, takes one clocked read of each state, constructs one detail, collects the keyed map, and returns the envelope. Consequently an unknown channel is absent rather than represented by the default detail; the default report and default detail are construction conveniences, not the result of a health read (`packages/assayer/src/risk/challenge.rs:555-584`). The method takes the sufficiency threshold from its caller even though the tracker also publishes a host-owned default of twenty (`packages/assayer/src/risk/challenge.rs:439-455` and `packages/assayer/src/risk/challenge.rs:559-575`).

The envelope is standalone in another literal sense: it is not a member of the Core's `SystemHealthReport`. That struct enumerates its complete Core report without a Companion field, and `Assayer::full_health_report` constructs only that Core shape (`packages/assayer/src/health/summary.rs:120-184` and `packages/assayer/src/api/health.rs:95-125`). A host that wants both must call and compose the independently owned tracker report itself.

Every field participates in Serde when the `serde` feature is enabled: the envelope and detail conditionally derive both `Serialize` and `Deserialize`, and neither has a skip, rename, or default attribute (`packages/assayer/src/risk/challenge.rs:595-618`). The map key and the nested estimate conditionally derive the same traits (`packages/assayer/src/types.rs:47-52` and `packages/assayer/src/types.rs:171-183`). Without that feature neither report type implements those traits. The repository tests state serialisation, but no test round-trips either health-report type (`packages/assayer/src/risk/challenge.rs:1083-1100`).

Repository-wide exact-name search finds no production call of `health_report`, no production reader of the envelope, and no reader at all of the detail's two override fields.

The metric catalogue does not change that census. It reserves `assayer_challenge_q_hat` and `assayer_challenge_sufficient_evidence` as per-channel host gauges, and no entry for the other four detail fields (`packages/assayer/src/metrics/catalog.rs:482-493`). `Host` means naming consistency only: no package mapper emits such an entry (`packages/assayer/src/metrics/catalog.rs:61-70` and `packages/assayer/src/metrics/catalog.rs:99-109`). The metrics tests prove both challenge names are absent from Core output and all challenge entries are host surface (`packages/assayer/src/tests/metrics_export.rs:809-829`), then prove generically that no mapper emits any host entry (`packages/assayer/src/tests/metrics_export.rs:955-991`). Thus `q_hat` and `sufficient_evidence` are the evident values behind the reserved names, but no shipped code feeds them; a host must perform that mapping.

The host-facing documentation is correspondingly split. Rustdoc describes the standalone clocked report and each member (`packages/assayer/src/risk/challenge.rs:555-618`); the module's test index says the report exposes estimate, variance, evidence count, and the sufficiency verdict (`packages/assayer/src/risk/challenge.rs:17-20`); the crate root exports the types (`packages/assayer/src/lib.rs:153-160`); and the deferred register calls Companion health host-owned and the Core metric names conventions (`packages/assayer/docs/deferred.md:255-264`). There is no host example, no health-report Serde test, and no documentation that maps the public fields to the two reserved metric names. All fields have Rustdoc. The documentation gap is therefore not an entirely undocumented field; it is one field omitted from the specification's enumerating table.

## The complete specified surface · `sec:challenge:companion-specified-surface`

The Companion chapter makes these health-surface promises, and no others:

- Its overview says that the health report, convergence bound, and boundary close the chapter with what a host can see, must wait for, and may rely on (`packages/assayer/docs/spec/companion-tracking.md:17-26`).
- The table is explicitly separate from Core health because the Companion converges and fails separately (`tab:companion:health`); `packages/assayer/docs/spec/companion-tracking.md:286-301`.
- The paragraph after the table makes variance contribution fraction the most actionable field, gives its one-half and one-tenth interpretation bands, and says three of nine rows ship while six do not (`packages/assayer/docs/spec/companion-tracking.md:303-312`).
- The amended convergence bound says that the effective sample size carried by the report remains the decayed evidence net of the prior under an override, and that the evidence needed before a channel counts as sufficient accrues at the same rate with or without the override (`bound:companion:convergence`); `packages/assayer/docs/spec/companion-tracking.md:314-331`.
- The boundary gives the host the bidirectional interface: feed contributing labels, read the estimate, posterior, and health report, and override or inject (`inv:companion:boundary`); `packages/assayer/docs/spec/companion-tracking.md:374-399`.

The output chapter adds no fields. It says the system report composes Core and Companion health, points readers back to this table, and explains that fields belong beside their computations rather than in a second hand-maintained list (`packages/assayer/docs/spec/reference-outputs.md:14-36`). The shipped `SystemHealthReport` does not perform that composition (`packages/assayer/src/health/summary.rs:120-184`). This is a second, outer-envelope divergence in the host-facing account: it does not change the field-to-row census, but a host reading only the output chapter will expect one combined report where the public API supplies two independently composed surfaces.

The row census in the table is correct: three of nine rows map to five shipped detail fields, and six rows are absent. The Rust-member census is also clear: five of six fields map to those three rows and one does not. The envelope's `channels` field is structural and is not a tenth datum.

The older audit's phrase “six of twelve fields ship” conflates those two counts. Expanding the paired table rows yields twelve specified atomic values: five ship and seven are absent. The sixth shipped Rust member is sufficiency, which is not among those twelve. The audit itself lists seven absent values immediately after claiming that six of twelve ship (`packages/assayer/docs/plans/spec-sections/parts-5-8.md:77-99` and `packages/assayer/docs/plans/spec-sections/parts-5-8.md:869-876`), while the outline repeats the misleading six-of-twelve shorthand (`packages/assayer/docs/plans/spec-outline.md:1066-1076`). This arithmetic does not change the table's own accurate three-row/six-row account.

## History and warrants · `sec:challenge:companion-history-warrants`

The divergence did not arise from a rename. Git blame places the envelope, the four original detail fields, the sufficiency field, and their defaults in `2de7cd1e` from 2026-05-15; `445463d6` added the override flag and values the next day. Their current declarations remain at `packages/assayer/src/risk/challenge.rs:595-633`. The rewritten Companion chapter and all nine table rows arrived later in `d8350bf3` on 2026-08-19 (`packages/assayer/docs/spec/companion-tracking.md:286-308`). Two minutes later, `8bd0d4ef` corrected the chapter to its present “three of nine rows ship” account (`packages/assayer/docs/spec/companion-tracking.md:309-312`). The table was therefore written with the six-member struct available, deliberately specified six currently absent rows, and omitted the already-shipped sufficiency verdict.

The later floor history strengthens rather than removes the omission. Commit `175cf3aa` moved the threshold out of Core construction and beside the host-owned tracker; `b8b3e300` applied the owner's 2026-08-22 ruling that the default is twenty. The constant now states that history and value (`packages/assayer/src/risk/challenge.rs:439-455`). Commit `cad9b1c2` corrected the bound for decay, and `a1927abf` then distinguished immediate use of an override from unchanged accumulation toward sufficiency. That last amendment created the chapter's one use of “sufficient” (`packages/assayer/docs/spec/companion-tracking.md:322-331`). Commit `7aa804d0` subsequently recorded that the table owes a row, but its accompanying premise that the chapter “never says the word” was already false (`packages/assayer/docs/plans/backlog.md:1937-1952`).

Four existing heads bear on a ruling:

- Health is diagnostic only. It blocks no path, withholds no output, and changes no behaviour (`dec:health:reports-never-gates`); `packages/assayer/adr/health.md:123-136`. A sufficiency row would therefore document a report verdict, not create a gate.
- The sufficiency floor belongs to the Companion beside the tracker whose health report reads it, not to Core convergence configuration (`dec:challenge:sufficiency-floor-owned-here`); `packages/assayer/adr/challenge.md:80-105`. This is positive warrant for the report to carry the verdict. It does not prescribe the table's typography, but it is incompatible with treating the verdict as an accidental Core field.
- The retained caveat now fixes the floor at twenty, states that it decides a reported Boolean, and records one crate-test reader but no production caller (`cav:challenge:sufficiency-threshold-open`); `packages/assayer/adr/challenge.md:165-205`. Its old “open” label does not leave the value open; the body records the later ruling.
- The convergence bound fixes the related operational meaning: twenty effective observations, accumulated independently of overrides, is the target; the sufficiency verdict is the comparison of the report's effective sample size with that host-owned floor (`bound:companion:convergence`); `packages/assayer/docs/spec/companion-tracking.md:314-360`. A row would expose the bound's verdict; it would neither duplicate the sample-size row nor make an override sufficient.

No existing head forbids a sufficiency row. The authoritative-specification decision means the shipped field does not amend the specification merely by existing (`dec:assayer:spec-authoritative`); `packages/assayer/docs/plans/backlog.md:682-692`. It reserves the edit for a recorded decision, which is why this report recommends rather than changes it.

One apparent contrary head is factually stale rather than prohibitory. The challenge record says no standalone Companion health surface exists (`cav:challenge:arrangement-open`); `packages/assayer/adr/challenge.md:145-163`, while the public producer, structs, and crate-root exports are present (`packages/assayer/src/risk/challenge.rs:555-618` and `packages/assayer/src/lib.rs:153-160`). The contracts-layer source repeats the same denial (`packages/assayer/docs/layers/layer5-contracts-and-boundaries.md:226-239`). That stale statement cannot license deletion or forbid documentation of a surface it overlooks. What genuinely remains absent is a package metrics mapper: the catalogue and its tests explicitly leave challenge emission to the host.

## Options · `sec:challenge:companion-owner-options`

### Option A — add the sufficiency row · `sec:challenge:companion-sufficiency-row`

Add one row to the binding table: a per-channel verdict that is true when the clocked effective sample size meets the host-owned floor, twenty by default, and is unchanged by an override. No other shipped detail field needs a row; the two pairs are already covered by “Estimate and variance” and “Override state.” Keep the six existing unbuilt rows as the specification's separate implementation gap.

- **Cost:** small documentation work. The source chapter and assembled `docs/spec.md` must agree, the table's conformance sentence becomes four of ten rows with six absent, and the outline and conformance audit must stop calling five matching atomic values “six of twelve.”
- **Risk:** low runtime risk because code, Serde, metrics, and behaviour do not move. The semantic risk is that adding a binding row adopts the already shipped and recorded verdict as specified API; that is exactly the decision this study cannot make.
- **Blast radius:** direct table readers are its convergence paragraph, the output-structures pointer, the assembled specification, and the outline (`packages/assayer/docs/spec/companion-tracking.md:314-331`, `packages/assayer/docs/spec/reference-outputs.md:24-36`, and `packages/assayer/docs/plans/spec-outline.md:1066-1076`). No repository code reader changes. Hosts gain a truthful description of a field and reserved gauge they can already consume. This option does not by itself resolve the output chapter's separate promise that Core and Companion health arrive as a composed system report.

### Option B — make the shipped struct match the present table · `sec:challenge:companion-contract-alignment`

The narrow form removes `sufficient_evidence`; renaming cannot erase the semantic extra because no present row describes a Boolean threshold verdict. The full-conformance form would also add the seven atomic values represented by the six missing rows. Those are materially different projects.

- **Cost:** removal is a public Rust and conditional-Serde schema break, plus changes to the report test, ruled-floor crate test, public default constant, metrics catalogue, and both challenge-record heads. Full conformance is much larger and adding fields is also source-breaking because the public structs are exhaustive: lifetime count, arrival-rate EWMA, and last-contribution time need new persistent state; the variance contribution fraction needs crossover context the standalone tracker does not currently receive.
- **Risk:** removal contradicts the current host-ownership ruling and hides the bound's actionable verdict. Full conformance risks changing persistence and ownership boundaries, especially for the fleet-level variance fraction.
- **Blast radius:** repository runtime behaviour is presently insulated because there is no production caller, but external hosts compile against the public re-export and may serialise the report. Tests and the two reserved host metric names are immediate repository readers of the contract (`packages/assayer/src/lib.rs:153-160`, `packages/assayer/src/tests/label_pipeline.rs:1102-1142`, and `packages/assayer/src/metrics/catalog.rs:482-493`).

### Option C — preserve and document the divergence · `sec:challenge:companion-documented-divergence`

Leave the nine-row table unchanged and state outside it that the implementation also publishes a non-specified sufficiency convenience, while continuing to track the six missing rows as specification debt.

- **Cost:** smallest immediate edit, but it needs a durable exception in the chapter, outline, and conformance register.
- **Risk:** high documentation drift for a small saving. The chapter says the table is the Companion's health report, the output chapter points hosts to it, and the records now treat the Boolean and its floor as owned decisions. A field outside the enumeration can change without either surface noticing.
- **Blast radius:** code and external Serde remain stable, but every host using the specification continues to miss the reserved sufficiency gauge unless it also reads Rustdoc or the exception.

## Study recommendation, and the decision it awaits · `sec:challenge:companion-recommendation`

Choose **Option A**. Add a single **Sufficiency verdict** row whose carrying text says that the channel's clocked effective sample size meets the host-owned floor, twenty by default, and that an override does not alter the verdict. Confidence is high. The field has shipped since May, the host-ownership decision places the floor beside this report, the later ruling fixes its value, the convergence bound now states its override-independent semantics, and report-only health contains its consequence. No source warrants deleting it or disguising it under another row.

Alongside that ruling, correct the dependent census to **four of ten semantic rows ship, six are absent**. When talking Rust members instead, say **all six members are specified by four rows** after the addition. Preserve the six currently unbuilt rows as a separate conformance question; adding sufficiency does not implement pseudo-counts, prior share, lifetime count, arrival rate, variance share, or silence age. Correct the two stale “no standalone health surface” caveats as factual maintenance rather than using them as policy. Track the output chapter's composed-report promise separately: adding the row does not decide whether the host or the package owns that outer composition.
