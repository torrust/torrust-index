# The Assayer Specification, Section Register: Parts V–VIII · `reg:assayer:companion-operations-and-analysis-register`

This is the section-depth register for Parts V–VIII of `docs/spec.md` — Chapters 18 through 30 and Appendices B through I — completing the chapter-level audit ([spec-audit.md](../spec-audit.md)) at subsection granularity. Every chapter and every appendix in the region is one entry below; every subsection is one row of that entry's table.

The document practices the discipline it serves. The label at each heading or environment head is that environment's mint; a parenthesized label in running text is a same-owner citation. Every label minted here has area `assayer`, and every kind is drawn from a fixed registry of environment kinds, under the grammar of the label calculus.

Two rulings govern the drift columns. Under *The specification is authoritative* (`dec:assayer:spec-authoritative`), where the code and the specification disagree the **code** is the diverging party; a DRIFT row records what the specification requires against what the legacy surface ships, and never proposes writing the code's behaviour back into the specification. Under *Upstream APIs held* (`dec:assayer:upstream-apis-scope`), the upstream summaries of Appendix H are not code-checked at all.

## Method and conventions · `sec:assayer:spec-sections-c-method`

**Convention (How the rows were produced and how to read them)** · `conv:assayer:spec-sections-c-method`

Six columns per row. *Section* is the pre-rewrite locator, in code font, carried only so a reader can find the text; it carries no identity and the outline discards it. *Subject* is what the subsection actually says. *Kinds* is the registry kind or kinds the material wants at the outline. *Binds* answers whether the subsection imposes an obligation on the implementation (yes) or explains, illustrates, or motivates one stated elsewhere (no); mixed subsections are marked part. *Status* is one of five: **SOUND** — a checkable claim, checked against the named code and found to hold; **DRIFT** — a checkable claim the code does not satisfy, stated in full in the verdict if it is new; **KNOWN-DEFERRED** — a claim the audited deferral register ([deferred.md](../../deferred.md)) already holds open, cited by its label and not re-described, per that register's own rule; **EXPOSITORY** — nothing checkable is asserted. *Evidence* is ``path:line`` under `packages/assayer/src`, read rather than inferred.

The distinction between DRIFT and KNOWN-DEFERRED is the point of this lane and is drawn narrowly. A deferral covers exactly the surface its completion trigger names. Where a specification claim is adjacent to a registered deferral but is not the thing deferred, it is stated as new drift and the adjacency is named, so that no finding hides behind a label that does not cover it. Three rows in Chapter 27 and one in Chapter 20 turn on precisely this.

Legacy tag forms of the superseded scheme (`dec:assayer:tags-superseded`) are written here as plain text, never in backticks, following the audit's own precaution: a three-level float tag of the old system — tbl:cfg:core, tbl:conc:tiers — is shaped exactly like a label of the calculus and would mint into the Assayer's owner if it were set in code font. Section-number locators are the legacy form that is safe in code font, because no backtick span of the shape `18.4` parses as a label. Tables are presentational: no cell mints.

## Part V — The Companion Tracker · `sec:assayer:spec-sections-part5`

**Entry (Chapter 18, Challenge Effectiveness Tracking)** · `entry:assayer:spec-sections-ch18`

Fourteen subsections, and the closest agreement between specification and code anywhere in this region — with three exceptions when this register was written, one of them sharp. The Beta-Binomial model, its conjugate update, its blend-toward-prior decay, the override with its 1/101 default variance, and every one of the four configuration defaults are implemented exactly as written. The exceptions were these, and two have since closed. First, the read-time decay convention that 18.4 and 18.7 state twice and tie to the Ledger's convention was **not** implemented: the code decayed only on write, and its own comment said read access was not clocked, so every estimate the host read was stale by the elapsed time since the last write. Both read methods now decay to the moment of reading, through a pure helper that mutates nothing, repaired in wave three against (`entry:assayer:wl-companion-read-decay`). Second, the Companion health report of 18.10 ships five of the twelve values it specifies; the struct's sixth member is the sufficiency verdict, which the chapter now specifies as a row of its own. That exception stands as found. Third, 18.14's replacement trait did not exist, which the chapter audit already found (obs:assayer:drift-companion-trait); it exists now with the defaulting posterior method the subsection asks for, repaired in wave eight against (`entry:assayer:wl-risk-replacement-trait`). The `posterior()` half of 18.4 and the ChallengePosterior type were carried here as unbuilt Part IV vocabulary (warn:assayer:drift-landscape-unimplemented); the type ships as that trait's carrier and the posterior is reachable through it, so only the Part IV *derivation* consumers remain unbuilt. Nothing in this chapter is in the deferral register: the register's one Companion line is a retirement, holding that Companion challenge-effectiveness health is host-owned, which disposes of Core metric naming and not of the report's own missing fields.

**Entry (Chapter 21, The Label Interface and Learning Pipeline)** · `entry:assayer:spec-sections-ch21`

Nine subsections, and the entry that carried this lane's most serious finding. The seventeen-step update path is present step for step and in order — the code's own label path is organised by the same numbering — and the buffer's concurrency, precision, and eviction behaviour are as specified. But 21.5.4 specifies reconstruction of the feature vector from six sources at label time, and the implementation reconstructed three: bias, the frozen Sentinel slots, and the frozen signal block. The identity block, the axis block, the aggregate block, and every interaction feature were left at zero in the vector every model was then trained on, with an explicit TODO at the reconstruction site saying so, while assessment-time vectors carried those blocks populated. The consequence was a systematic divergence between the vector a prediction was made from and the vector the update was applied to, across roughly a fifth of the reference configuration's dimensions. It was nowhere in the deferral register and nowhere in the chapter audit. The pending entry's field list corroborated it from the other side: the four stored components 21.5.1 requires for the missing reconstruction steps were themselves absent from the struct.

Both halves have since closed, in the order the finding said they had to. The pending entry gained its four missing components first, so that the inputs the missing steps consume are retained, repaired in wave six against (`entry:assayer:wl-pending-entry-fields`); the reconstruction then gained the three blocks it was skipping, repaired in the same wave against (`entry:assayer:wl-phi-reconstruction`). All six numbered sources are populated now, the TODO is gone, and a debug write-coverage assertion catches any position written outside a declared block. The chapter's serious finding is discharged; what remains of this entry is the record of what it found.
