# The testing-harness record audit · `rep:assayer:testing-harness-record-audit`

This report projects the testing-harness concept (´plan:assayer:testing-harness-concept´) onto the Assayer decision-record system. It is evidence and allocation, not a decision, register, backlog, or record: every table is a reading table under the outline's column convention (´conv:assayer:record-outline-columns´), and a label this report proposed that the corpus has not minted stays in a double-backtick span, so that no cell resolves into an environment that does not exist.

The projection has since been carried out, and this reading is re-taken against the result. The shared testing contract is a landed record (´rec:harness:shared-testing-contract´) admitted by an outline ruling (´dec:assayer:record-harness-record´); its behaviour-specific consequences extend the records that own those behaviours; the open work became backlog entries under one campaign section (´sec:assayer:campaign-testing-harness´); and the harness itself was built (´plan:assayer:harness-implementation´). Each proposal below therefore resolves to the environment that carries it, to the environment that replaced it, or to the question that is still open.

## Method · `sec:assayer:testing-harness-record-audit-method`

The reading began with the backlog's standing rulings, the record-set outline, the record register, the deferral register, and the repository label-calculus summary. It then covered every environment in the record set, the concept and its architecture and testing-plan context, the cited specification parts, the full layer set, and the entry heads of the full intent-plan set. Each intent plan in the specification-conflict subset was then read in full.

Claims about presence, absence, counts, areas, kinds, citations, and collisions are checked twice: first by reading the environment that establishes the claim, then by a repository search over the Assayer corpus. Claims about what a record decides are made only after reading every environment head and body in that record; a filename, table position, or concept summary never stands in for that reading.

The basis is re-taken at the commit recorded below, by the search that produces each figure. The record count and the environment census come from the register's tracking rows, which carry one row per environment of every landed record and are checked against those records in both directions (´conv:assayer:record-register-tracking´); counting the mints in each record document reproduces both figures independently, and the two searches agree row for row. The kind list is the distinct kinds those mints carry. The concept census counts the mints in the concept. The specification and layer figures resolve this report's own specification and layer citations to the documents that mint them. The intent-plan figures count the plan documents, and the production-change figure counts the plans whose what-is-missing entries name a change to production source. The citation figures count parenthesised label citations, resolve each distinct label to the document that mints it, and report a collision wherever two documents mint one label.

Every table in this report is a reading table. None has the tracking-table semantics stated by the record register (´conv:assayer:record-register-tracking´).

## The projection · `sec:assayer:testing-harness-record-audit-projection`

The projection principle makes the records a projection of layer choices, and the derivation rule fixes a unique coherent home for every live decision (´dec:assayer:projection-principle´) (´req:assayer:record-derivation-rule´). A testing-harness contract controls tests rather than specifying Assayer behavior, so it cannot be manufactured as another layer-derived product decision. Its behavior-specific consequences belong in existing records; its cross-cutting test semantics need a dedicated record only if keeping them elsewhere would copy or mis-home them.

The recommendation was a new record with area ``harness``, and that is what the outline admitted (´dec:assayer:record-harness-record´). Like the clock record (´dec:assayer:record-clock-record´), it earns a place by preventing an indivisible discipline from being divided among nominal homes that do not govern it. Folding the whole contract into ``construction`` would make construction own playback, oracle provenance, fixture validity, and wait vocabulary; splitting it across several records would erase the shared rule that makes those pieces a coherent harness. The landed record stays inside the derivation band and carries decisions rather than a registry (´entry:assayer:record-harness´).

The strongest alternative was no new record: keep test-only choices in the testing plan, add only the behavior-specific corollaries and caveats to existing records, and let the test documentation policy govern evidence. That option preserves the strict layer-derived set and correctly observes that tests do not change the specification. It lost because a plan states an argued opinion rather than a durable decision, while the shared scenario, no-wait rule, probe boundary, oracle provenance, and fixture obligation are standing alternatives that future tests must cite after the implementation plan retires. The ruling records that rejection on the same ground (´dec:assayer:record-harness-record´).

## Findings · `sec:assayer:testing-harness-record-audit-findings`

**Observation (The records constrain the concept but do not contradict its choices)** · `obs:assayer:testing-harness-record-audit-no-record-conflict`

No primary concept decision contradicts an existing record. The apparent conflicts are premises the records have already settled: the separated clock domains, per-request snapshot load, absence of a batch view, retention exclusions, production opacity, host declarations, and the debug-oracle precedent. Formalization cited those heads and recorded only the remaining test-contract alternatives, which is what the landed record does clause by clause (´rec:harness:shared-testing-contract´).

**Observation (The acceptance universal conflicts with the retention resolution)** · `obs:assayer:testing-harness-record-audit-probe-universal-conflict`

The concept said every test-tree state projection uses the probe contract, while its retention risk sends witnesses of deliberately excluded state to direct crate-level access. Both could not stand literally. The defect is discharged: the record keeps retention strict and the concept's acceptance now quantifies over the projections the test-support contract permits, with excluded state left to a direct crate-level witness (´cav:retention:probe-boundary´) (´sec:assayer:testing-harness-concept-acceptance´).

**Observation (The current architecture contradicts the target state as evidence, not policy)** · `obs:assayer:testing-harness-record-audit-architecture-gap`

The architecture report found several scenario models, a polling wait that can return stale progress, a specialised tree that repeats routing, and callerless or stale harness material (´rep:assayer:testing-architecture´). Those readings established retirement work and fails-before evidence rather than authorizing current implementation structure into the record. The retirement work has since run: the scenario models merged, the waits retired behind named barriers, and the callerless and staging findings are discharged at their own heads (´entry:assayer:harness-scenario-unification´) (´entry:assayer:harness-polling-retirement´) (´obs:assayer:testing-architecture-unreported-decay´) (´obs:assayer:testing-architecture-staging-notes´). The routing duplication remains, and remains the evidence for the side-harness boundary rather than a defect (´obs:assayer:testing-architecture-routing-duplication´).

**Observation (The new record is a controlled exception to the strict derivation)** · `obs:assayer:testing-harness-record-audit-derivation-exception`

The record set projects the layers, which project specification choices. The harness record projects neither a new specification behavior nor a new layer, so it earns its place only through an explicit outline ruling analogous to the clock precedent: a cross-cutting discipline would otherwise be copied or assigned to records that do not govern tests. The condition was met in the order it required — the ruling landed in the outline before the record and its register rows (´dec:assayer:record-harness-record´), and the master table keeps the exception distinct from the eighteen layer-derived records (´tab:assayer:record-set-master´).
